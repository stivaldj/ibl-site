# Roadmap Archive: VARIANT v1.0

**Archived:** 2026-03-20
**Milestone:** `v1.0`
**Theme:** Production hardening
**Status:** Shipped

## Snapshot

This milestone turned the existing VARIANT site from an ad hoc brownfield build into a production-hardened baseline. The work prioritized customer-facing experience, lead-flow reliability, SEO/content trust, deterministic generation, and a formal launch gate before allowing future feature expansion.

## Delivery Summary

- **Phases:** 6
- **Plans:** 18
- **Tasks:** 37
- **Requirements satisfied:** 21 / 21
- **Audit status:** Passed
- **Archive source:** `.planning/ROADMAP.md` and `.planning/REQUIREMENTS.md` as of milestone closeout

## Phases

### Phase 1: Site Experience Stabilization

**Goal:** Remove the most visible browsing, layout, and CTA defects across homepage, generated catalog/category/product routes, and mobile entry points.

**Plans:**
- `01-01` Stabilize homepage and mobile entry shells
- `01-02` Fix repeated catalog/category/product defects at the generator/template level
- `01-03` Normalize shared runtime behavior across entry scripts
- `01-04` Close the generator-level CTA-anchor gap

**Outcome:** Representative browse journeys now work cleanly across `/`, `/mobile/`, `/produtos/`, category routes, and representative PDPs, with generated CTAs aligned to `/#captacao-lead`.

### Phase 2: Lead Flow Hardening

**Goal:** Make lead capture dependable, observable, and consistent across desktop, mobile, and generated product flows.

**Plans:**
- `02-01` Add a repo-local mock webhook harness
- `02-02` Stabilize shared lead payload and submit-result semantics
- `02-03` Make user feedback and `?ops=1` observability honest
- `02-04` Close the contacted-lead SLA-risk gap

**Outcome:** Homepage, mobile, and product lead flows now use one stable payload contract, explicit success/skipped/failure outcomes, truthful feedback, actionable ops visibility, and corrected SLA-risk logic.

### Phase 3: SEO And Content Trust Hardening

**Goal:** Move launch-critical metadata and trustworthy machine content into generated HTML and eliminate fragile runtime SEO dependence.

**Plans:**
- `03-01` Move metadata/schema into the generator
- `03-02` Fix representative machine-content trust defects
- `03-03` Downgrade runtime SEO to fallback-only behavior

**Outcome:** Generated routes now ship canonical/meta/social/schema directly in source HTML, and representative product/category content stays aligned with source data.

### Phase 4: Generation And Frontend Reliability Stabilization

**Goal:** Make generation, assets, packaging, and rebuild operations deterministic enough for safe reruns and future work.

**Plans:**
- `04-01` Harden the Python generation and asset pipeline
- `04-02` Make the production packaging path honest for the full site surface
- `04-03` Document and verify the rebuild workflow end to end

**Outcome:** Generation reruns are deterministic enough for launch continuation, `dist/` now contains the real launch surface, and `docs/OPERATIONS.md` defines the authoritative rebuild path.

### Phase 5: Launch Verification And Operations Gate

**Goal:** Define the formal launch gate and produce durable evidence for rebuild, smoke, mobile, and lead verification.

**Plans:**
- `05-01` Define the formal launch checklist and helper commands
- `05-02` Execute the gate and publish the readiness decision

**Outcome:** The repo gained a formal launch gate, evidence outputs under `.tmp/launch-gate/latest/`, and a written launch-readiness decision.

### Phase 6: Launch Gate Completion

**Goal:** Close the milestone audit gaps around launch-gate reproducibility and scope.

**Plans:**
- `06-01` Make the lead gate repo-native and strict
- `06-02` Re-run the tightened gate and refresh readiness evidence

**Outcome:** The release gate is repo-native, validates homepage/mobile/product success and failure modes, and enforces WhatsApp handoff as a real pass condition.

## What Shipped

- Customer-facing browse flows are stable across homepage, mobile, catalog, category, and representative PDP routes.
- Lead capture is verifiable locally and behaves consistently across supported surfaces.
- Generated SEO and trust signals now live in source HTML instead of depending on runtime mutation.
- Generation and packaging workflows are deterministic enough for repeatable rebuilds.
- The repo contains a formal launch gate and fresh evidence showing readiness for production continuation.
